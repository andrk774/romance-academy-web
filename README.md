# Romance Academy 7 — веб-версия

**Играть в браузере:** https://andrk774.github.io/romance-academy-web/

**Исходники:** https://github.com/andrk774/romance-academy-web

Самостоятельная браузерная адаптация проекта Romance Academy 7 / Rokko System. Не требует Ren’Py, сборки или установки npm-зависимостей.

## Запуск

Нужен Node.js 22 или новее. Откройте терминал в корне этого репозитория:

```powershell
npm.cmd start
```

Откройте http://127.0.0.1:4173. Для игры без серверного ИИ можно также открыть `dist/index.html` напрямую; сохранения для `file://` зависят от браузера. Для стабильных сохранений рекомендуется запуск через сервер.

## Что перенесено

- Оригинальные изображения класса, спрайты и музыка из `game/`.
- Знакомство с Giffany: книги, шутка про кальмара, интересы и приглашение после занятий.
- Спортзал Sully и литературный клуб Monika, повторные встречи.
- Русская адаптация диалогов, ветвящиеся выборы, отдельные отношения с каждым персонажем, харизма, дни.
- Карта, дневник, история реплик, анимация речи, автоматическое чтение, полноэкранный режим.
- Автосохранение в браузере, импорт и экспорт JSON, настройки музыки и скорости текста.
- Автономный чат по сценариям. Он явно обозначен как режим без ИИ.
- Серверный адаптер ИИ для локального запуска.

Это перенос основного игрового цикла с адаптированными сценами, а не интерпретатор всех `.rpy`. Не перенесены незавершённые эпилоги, ClamAV, запуск программ Windows, поиск процессов DDLC, генерация контрактов и фоновые голосовые демоны. Браузерная игра не читает личные файлы и не запускает программы компьютера. Исходная Ren’Py-игра не изменена.

## Чат с ИИ

1. Скопируйте `.env.example` в `.env`.
2. Укажите `LLM_API_URL` (совместимый с `/v1/chat/completions`), `LLM_MODEL` и при необходимости `LLM_API_KEY`.
3. Перезапустите `npm.cmd start` и обновите страницу.

Для Ollama укажите имя действительно установленной у вас модели. Для облачного провайдера используйте HTTPS. Старые ключи из `llm_config.ini` автоматически не копируются. Ключ хранится только на сервере, `.env` исключён из Git, статический сервер отдаёт только файлы `dist/`. Ошибки провайдера не раскрывают его ответ или ключ пользователю. Один запрос игрока вызывает один запрос к модели. Ответ вставляется через `textContent`, поэтому HTML и теги Ren’Py не исполняются. Команды модели не изменяют игровые характеристики.

Развёртывание `dist/` на статическом хостинге включает автономный чат. Для ИИ нужен собственный сервер с `server.mjs` и переменными окружения; перед доступом из интернета добавьте аутентификацию и HTTPS на обратном прокси. Локальный сервер слушает только `127.0.0.1`.

## Сохранения

Прогресс хранится в `localStorage` отдельно для каждого адреса сайта. Переход с локального адреса на опубликованный сайт не переносит сохранение автоматически: используйте экспорт/импорт в настройках. Очистка данных браузера удаляет прогресс. Очки за один и тот же выбор выдаются один раз, чтобы повторное посещение сцены не позволяло бесконечно их накапливать.

## Обновление GitHub Pages

Ветка `main` содержит исходники и локальный сервер, ветка `gh-pages` — только содержимое `dist/`. После изменения и коммита игры в `main` выполните:

```powershell
git push origin main
git subtree push --prefix=dist origin gh-pages
```

GitHub Pages автоматически публикует ветку `gh-pages`. На Pages доступен автономный чат; для ИИ запускайте серверную часть отдельно.

## Проверка тестами

```powershell
npm.cmd test
```

Тесты проверяют переходы сюжета, сохранения, начисление очков, разделение персонажей, статические ресурсы и ограничения HTTP/API. Браузерная проверка находится в `tests/browser.cjs` и требует уже установленного Playwright; путь можно передать переменной `PLAYWRIGHT_PATH`.

Материалы исходного проекта сохранены без изменения авторства. Перед распространением отдельно убедитесь в правах на изображения и музыку.
